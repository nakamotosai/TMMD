# TMMD 竞品调研与功能差距分析

> 日期:2026-10-24 · 对象:TMMD v1.6.0(`F:\projects\tmmd`,HEAD `94f29cd`)
> 方法:三名分身并行调研(商业阅读器 / 知识库应用 / 视觉设计标杆)+ 本机源码与运行态实测。
> 所有"竞品有/没有"的结论来自官方文档或官方页面;所有"TMMD 有/没有"的结论来自源码或本机实测。

---

## 0. 结论(TL;DR)

1. **功能广度不是我们的战场。** 57 项能力清单里 TMMD 拿到 **32 / 57 ≈ 56%**(去掉定位外类别 62%);缺的都是"不属于只读阅读器"的东西(插件生态、双链图谱、同步、跨平台)。**真正该补的只有 4 项**:文内搜索、脚注、行宽/行高与自定义 CSS、外部文件变更自动刷新。
2. **外观是主战场,而且现在的差距不在"够不够透明",在"够不够精致"。** 透明亚克力的可调深度我们已经超过所有竞品(Windows 版 Obsidian 已移除透明;Typora/MarkText 没有;只有 Windows Terminal / Warp 有同类可调性,深度还不如我们),但**排版、层级、动效、默认窗口尺寸**四项拖后腿。
3. **一个反直觉的结论**:微软官方规范明确写着 **"不要把 desktop acrylic 铺在应用的大面积背景上""Acrylic 是 GPU 密集的"**,只推荐用于瞬态表面。我们现在的"整窗亚克力"正好踩在规范的反面 —— 正确的高级做法是 **Mica / Mica Alt 打底(整窗,零性能代价)+ 只在标题栏、侧栏、浮层用 Acrylic 模糊**。视觉上"透"的感觉来自**分层**,不是来自"整块糊"。
4. **一条硬指标**:白字直接压在模糊底上只有 **3.95:1**(不达 AA 4.5:1)。所以透明必须有**遮罩下限**(深色底 α ≥ 0.55 才够 4.5:1,要 7:1 得 0.65)。"最好看"的前提是"看得清"。

### 3.2 标杆的共性做法(调研结论)

- **层级靠明度差,不靠阴影**:Windows 11 原生 = Mica 铺满整窗 + 内容层一层 50%/30% 半透明实色 + 统一 1px 描边 + 8px 圆角。(微软 Mica/分层规范)
- **玻璃是"状态"不是"底材"**:Linear 只在 hover/active 用 `blur(8px) + #ffffff29`;Raycast 玻璃只做一次性容器(`blur(36px) + #0009 + 1px #8e8c9066`),交互反馈仍走 ≤200ms。
- **减法比特效更显高级**:iA Writer 干脆没有标题栏("removes anything that gets in the way");Things 3 完全没有透明效果,照样两次拿 Apple Design Award。**"透"不等于"好看"**,留白与节奏才是。
- **透明度拆成两个开关更专业**:Windows Terminal 把"模糊(useAcrylic)"和"不透明(opacity)"分开,并允许"只要半透明不要糊"。
- **平台化 token**:Raycast 的 Windows 变体把窗口圆角从 26px 降到 8px、字体换 Segoe UI Variable —— 一个产品两套 token,不硬套 mac 观感。
- **中文排版数值**:正文 16→18px、行高 1.6–1.75、行宽 32–38 全角字(≈ `max-width: 34em`)、代码块底板 α ≥ 0.9、图片加 1px 描边 + 不透明底。

## 4. 战略:把"透明"做成"高级的透明"

### 4.1 修正认知(有官方依据)

微软对 Acrylic 的两条硬约束:
- 「不要让 desktop acrylic 铺在应用的大面积背景上」「不要并排多个 acrylic 面板(会出现可见接缝)」;
- 「Acrylic 的渲染是 GPU 密集的,会增加功耗、缩短续航」;而 Mica「只采样壁纸一次,为性能而设计」。
- 且材料在**窗口失焦、节电模式、关闭"透明效果"、系统版本不足**时会**自动回落成实色**。

⇒ **整窗 Acrylic 是"当前版本的权宜",不是终极形态。** 终极形态建议:

```
整窗:Mica(或 Mica Alt)             ← 长驻、零性能代价、失焦自动退场
 ├─ 内容层:#4C3A3A3A 级半透明实色压在 Mica 上(深色)
 ├─ 标题栏 / 侧栏 / 弹层:Acrylic 模糊(面积小、瞬态语义正确)
 └─ 正文滚动区:不透明底板(α≥0.9),绝不 blur ← 滚动流畅 + 对比度可控
```

### 4.2 但"看得见的透明"必须保留(这是卖点)

折中方案:给用户 **"材质"三选**(无 / Mica / Acrylic)与 **"通透度"一滑**,其中:
- 深色底遮罩 **α ≥ 0.55** 才能保证白字 4.5:1;**α ≥ 0.65** 才有 7:1;
- 透明度下限锁在 **60%**,滑到最低时正文/代码块/表格自动提到 α ≥ 0.9(参照 Windows Terminal 的"标签行单独一档"思路);
- 提供"只要半透明、不要模糊"的档(Win11 上 acrylic=false 的不模糊透明),照顾低端 GPU 与节电模式。

### 4.3 签名视觉(建议固定下来的 5 件事)

1. **标题栏 32px**,圆角 8px(Windows 变体),失焦时标题栏元素整体降透明度。
2. **层级 token 抄 WinUI**:`Layer` / `Card` / `Control` 三级 + 统一 1px 描边(浅 `#0F000000`、深 `#12FFFFFF`),圆角收敛到 4/8/12/16 四档。
3. **中文排版换血**:正文无衬线(思源黑体/霞鹜文楷 UI 可选),行宽 `max-width: 34em`,行高 1.7,字号下限 16px;等宽只留给代码。
4. **动效统一 150–200ms ease-out**:文档切换 120ms 淡入、玻璃开关做"结霜"过渡、空态 logo 加一次入场;不做循环动画。
5. **空态即海报**:现在是"大片空白 + 橙字",应做成品牌画面(logo 动效 + 最近文件磁贴),这是第一眼印象。

## 5. 路线图(按"最好看"排序,不是按功能多寡)

### P0 —— 不改就不算"最好看"(预计 1.5–2 天)
1. **默认窗口自适应**:按工作区 88% 初始化 + 记住上次尺寸位置(本机 4K@225% 下 800×800 只占可用宽 47%,方形窗口不随屏幕走;另:窗口小于 640 逻辑宽时侧栏会自动折起,旧阈值 780 会让小屏每次开机都折)。
2. **排版换血**:中文正文无衬线、行宽 `34em`、行高 1.7、代码块 α≥0.9、图片 1px 描边;新增"行宽/行高"两个滑条(进设置页,和字号预设并列)。
3. **层级与景深重建**:抄 WinUI 三级 + 1px 描边 + 四档圆角;标题栏/侧栏/浮层与正文分层。
4. **透明可读性下限**:α 下限 60%、正文区强制不透明底板、强调色不压玻璃。

### P1 —— 让它"耐看"(2–3 天)
5. **材质三选(无 / Mica / Acrylic)+ 失焦与节电回落**:把"关闭透明效果"做成一等状态。
6. **动效体系**:150–200ms 统一时长、文档切换淡入、玻璃"结霜"过渡、空态品牌入场。
7. **文内搜索**(Ctrl+F 高亮 + 上下条 + 命中计数)——功能上最刺眼的洞,且对阅读体验加分明显。
8. **设置页视觉重做**:12 行纯文字行 → 分组卡片 + 图标 + 右侧预览,（现在右侧留白过大)。

### P2 —— 差异化加分(3–5 天,可选)
9. 跨文件全文搜索(库级索引)。
10. 脚注 + 定义列表 + 代码块行号/复制按钮(低成本补齐"保真度")。
11. 外部文件变更监听(库级 watcher + toast 提示"磁盘已更新")。
12. 导出 PDF / 打印样式表(把已经好看的排版落到 PDF)。
13. 专注/打字机模式(iA Writer 那套"其余淡出"而非隐藏)。
14. UI 多语言(README 已经三语,UI 跟不上)。

### 明确不做
插件生态、双链/图谱、云同步/E2EE、跨平台、数据库式属性 —— 这些是"最强"的赛道,与"最好看 + 只读 + 本地优先"冲突。
