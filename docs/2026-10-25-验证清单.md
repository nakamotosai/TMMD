### 独立复查(2026-10-25)

只读分身复查 `9362472` 抓出三类问题,已逐条修并加了对应回归:
①`r12f` A4 **恒真假绿**(拿剥过字符串的源码扫 `t('key')`,匹配 0 次)→ 改用只剥注释的源码 + 作用域按最近围栏算 + 新增 A5 自检;
②**i18n 只翻一半**(复查把 lib.rs 全部命令层中文串喂进 `trErr`,90 条仍含中文)→ ERR_MAP 补到 41 条规则、5 条消息的中文尾巴改成数据 + 新增 E11 覆盖度断言(EN 下零中文残留);
③`r12d` `runWithAsk` 丢 `clicked`(弹窗没弹也算过)→ A51 现在要求真弹窗真点击。

### 运行验证**抓到并修掉**的 5 个真缺陷(全部是上静态检查漏掉的)

1. **保存/冲突路径 TypeError**:i18n 批量替换把 `String(trErr(e))` 写成了 `StringtrErr(e)` ——
   `writeTabContent` 的 catch 一执行就 `ReferenceError`,`printCurrent` 同款。
2. **i18n 调用被局部 `t` 遮蔽**:`activateTabRaw(t, opts)` 的参数叫 `t`、`closeTab` 的局部也叫 `t`,
   `t('toast.x')` 变成"把 tab 对象当函数调"→ TypeError。**读文件失败提示**与**关脏标签冲突**两条路全崩。
3. **导出 HTML / PDF 恒失败**:`getTab(S.cur)` 传的是对象 `{abs,raw}` 而不是路径,恒 `undefined`
   → 点「导出 HTML / 导出 PDF」永远弹"还没有打开任何文档"。
4. **PDF 直出找不到浏览器**:只查 ProgramFiles 下三处固定路径;本机根本没装 Edge/Chrome。
   已补:注册表 `App Paths`(HKLM/HKCU)+ Brave/Vivaldi/Chromium + `TMMD_PDF_BROWSER` 显式指定。
5. **控制台闪窗**:`reg` / `cmd /C start` / 更新器 `powershell` **都没加 `CREATE_NO_WINDOW`** ——
   GUI 进程起控制台子进程时 Windows 会新建一个可见控制台窗口,**闪在用户桌面上**。
   这是用户抱怨"疯狂弹我主屏幕"的一类真实来源;现在 5 处 spawn 统一走 `hidden_cmd()`。

## 1. 起一个"看不见"的隔离实例(唯一正确姿势)

```powershell
# 一次只发一条命令;本条约 5 秒返回
powershell -File tools/verify/launch-on-secondary.ps1 `
  -Exe F:\projects\tmmd\src-tauri\target\debug\tmmd.exe -Port 9225
```

脚本做的事:①按副屏工作区算几何并写进**隔离配置目录**;②`TMMD_TEST_NOACTIVATE=1`
(SW_SHOWNOACTIVATE + WS_EX_TOOLWINDOW:不抢前台、不进任务栏);③CDP 端口给 e2e 用;
④把 PID 落盘给 `stopall.ps1`。

验收输出必须满足:`FIRST visible real window: <副屏坐标>`、`touchedPrimaryScreen=False`、`onSecondary=True`。

**隔离边界(2026-10-25 加固)**:`TMMD_CONFIG_DIR`(roots/window/update_state/updates 全在内)
+ `WEBVIEW2_USER_DATA_FOLDER`(localStorage/WebView2 缓存)——自动化实例**完全不碰**用户真实配置与标签。
此前没隔离,测试实例会继承用户真实标签(实测:启动就恢复了用户的 `F:\knowledge\...` 页面)。

改过 `ui-reader/*` 之后**必须先 `cargo build`** —— 前端是编译期嵌进二进制的。

## 6. 已知的坑(踩过,别再踩)

1. **PS 脚本必须 ASCII**:Windows PowerShell 按 ANSI(本机 GBK)解码 `.ps1`,中文会串码并吃掉换行。
2. **一次一条命令、每条短**:并发或长命令会触发"临时 shell"/后台作业 —— 那会在用户桌面上**弹一个真终端**。
   长活(构建、跑跑道)请放到一个**隐藏的**进程里(本机做法:Python `subprocess` + `CREATE_NO_WINDOW`,输出重定向到日志文件)。
3. **不要在自动化里起会弹 UI 的东西**(`cmd.exe`、安装器):失败会弹系统错误框。失败必须落日志文件。
   同理:产品代码里所有控制台子进程都必须 `CREATE_NO_WINDOW`(见 §0 缺陷 5)。
4. **测试脚本必须有沙箱护栏**:只允许在 tmp 沙箱文件上输入/保存(r12e 的 `guardSandbox()`)。此前把仓库 README 写成了一行。
5. **改前端必须重建**;重建前先 `stopall.ps1`,否则 exe 被占,`cargo build` 报 `os error 5`。
6. **跑道之间要等页面就绪**(`r12d` 结尾 reload,不等就 `S is not defined`)。
7. **`window.confirm` 已经不是离开编辑态的弹窗**:v1.8 起走三选弹窗 `askUnsaved`。
   在同一条 `Runtime.evaluate` 里 await 一个"会弹窗"的动作**必然超时**(没人能点按钮)。
   正确手法:把动作挂到 `window.__pending`,另发一条 evaluate 点掉弹窗,再取结果(r12d 的 `runWithAsk()`)。
8. **陈旧期望要更新,不要放过**:r12d 这次 12 条失败全是"测试写死了旧数字"(设置 26 行→28 行、
   玻璃四数→单一浓度、`window.confirm`→三选窗),**不是产品缺陷**;但也不能直接删,要改成 New 语义下的真断言。
9. **注释里出现 `t('toast.x')` 会被朴素扫描器当成代码**:做 i18n 键扫描前先剥注释与字符串(否则误报)。
10. **字典键重复会被后者覆盖**(`err.tooBig` 曾有两份),新文案静默失效 —— r12f E9 现在盯这条。

## 7. 更新器「真装一遍」演练(2026-10-25,已实跑)

#    TMMD_UPDATE_ENDPOINT=http://127.0.0.1:8799/latest.json
# 3) 页面内走完整链:update_check → update_download → update_install → allow_close → 关窗

### 8.6 更新通道 BOM 事故(当天连修两版的原因)

做完 v1.8.1/v1.8.2 的发布后跑"真链路"检查,客户端报 `更新清单无效: expected value at line 1 column 1`。
查实:`latest.json` 首三字节是 `EF BB BF` —— PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写 UTF-8 BOM,
而 `serde_json::from_str` 见 BOM 直接拒。**对外资产能下载、对内一律失败,而且看起来完全正常**。

两面都修:发布脚本 `make-release-manifest.ps1` 显式写无 BOM;客户端解析前 `trim_start_matches('\u{feff}')`。
现在 `tools/verify/update-manifest-check.py` 四例全绿,其中"真链路"那一例用的就是**线上仍带 BOM 的 v1.8.2 清单** ——
即客户端容错在真资产上生效的直接证据。

另:当天还踩到**单实例**这个坑 —— 装好的实例在跑时,验证实例一启动就把 argv 转给它在跑的那个然后退出,
启动器干等到超时(表现为"窗口永不出现"+ 四条核验全 FAIL)。现在启动器见到任意 `tmmd.exe` 存活就明确报错,
`stopall.ps1` 加了 `-IncludeInstalled`(默认仍不碰你自己那台)。

6. **`r12g` 第 23 条的焦点环断言对 DPI 敏感**。Chromium 在非 100% 缩放的屏上会把 computed 长度按 zoom 折算:
   同一枚 2px 环,在 200% 副屏读作 `2px`,在 225% 屏读作 `1.77778px`(= 2 × 2/2.25)—— 但**物理宽度都是 4 设备像素**。
   原来直接比 `>= 2px` 会"换个屏就假失败"。现在乘回 `devicePixelRatio`,断言 **≥3.5 设备像素**(CSS 基准 2px @2x),
   两边都真绿且判据不退。
7. **子进程继承管道会让 Python 编排永远等 EOF**:`subprocess.run(capture_output=True)` 在 timeout 杀掉直接子进程后,
   仍要等管道 EOF,而启动器拉起的 `tmmd.exe` 握着那个写端 → 实测卡满 40 分钟(不是超时能救的)。修法:凡会拉起 GUI 的调用
   一律 `stdout=文件`。同类坑当天踩了三次,已写进 `tools/verify/update-manifest-check.py` 的注释。

### 9.2 PDF 直出:本机"有 Chromium"但**不能当打印内核**(正例仍不成立,病灶已定位)
