# Changelog · TMMD

## v1.8(未发布)· 2026-10-25

### 整窗一整块玻璃(用户定调:对标 pebrel 的"一整块玻璃",不走规范式分层)
- **单一浓度**:四路 `--glass-base/chrome/reader/pop` 收成 `--glass`;氛围档 weak/medium/strong = 20/45/70(medium 即 pebrel 配置里的 `opacity=0.45`)。老存档按 `1-(1-base)(1-reader)` 折算成单一浓度,视觉不跳。
- **只画一层**:`html` / `.layout` / 铬层 / 正文区不再各自叠浓度(旧模型 base 被叠 2–3 次,总浓度不受控);`body` 成为唯一浓度层。
- **DWM 只做模糊**(与 pebrel 实测配方对齐):`glassSplit(conc)` 现在返回 `{ dwm: 1, css: conc }` —— 浓度全由页面层画,DWM 只保住 accent 通道(alpha 不能取 0,否则部分 DWM 版本会跳过,玻璃整块消失;pebrel 同样写 `0x01000000`)。依据其源码:`blur=acrylic` 首选 WinAppSDK `DesktopAcrylicController`(`tint=0`、`luminosity=0`),回落 `WCA accent state 4`;它的 `opacity=0.45` **只乘自己画的背景色**(壳色/标题栏/侧栏/卡底),文字与图标始终不透明 —— 与我们"单一浓度 + 文字 alpha 独立"的模型一致,滑条也因此诚实(写 45% 就得到 45%)。
- **实测(副屏真实合成像素,同一张壁纸)**:跨表面边界同高度取样(顶栏→正文、侧栏→正文、侧栏底→正文、设置页导航→主体)Δ = 0.0–1.4 luma → **"一整块"成立**;正文留白沿壁纸连续变化(135→133→108→96→103→131→127),无分块跳变。最坏情况对比度(`--fg` 压在窗内最亮壁纸带):conc 45 → 中位 3.71:1 / 最坏 2.15:1;conc 70 → 6.35:1 / 3.21:1(纯白壁纸模型对应 2.17:1 / 4.55:1)。**默认浓度待用户定**。
- 另注:只设 `DWMWA_USE_HOSTBACKDROPBRUSH=1` 而不接 WinAppSDK 的 composition target **无任何视觉变化**(实测前后像素完全一致);pebrel 那条现代路线需要 ~200 行 COM 互操作(WinAppSDK 1.8 + `DesktopWindowTarget`),而我们的 WCA 回落路径与它的回落路径同级。
- **内容板不再是补丁**:31 处 `background: var(--bg2|--bg3|--code-bg|--bg)` 换成 `--surface-plate`(浓度 +22)/`--surface-plate-strong`(+40);代码块不再强制不透明。
- 修:`applyAtmos` 还在往存档写已废的 `base/chrome/reader/pop`(全是 `undefined`)→ 氛围档按钮失效;`.setpage-search` 在设置页里又垫了一层窗口级浓度。
- 实测(副屏抓真实合成像素):Mica 确认真机生效(`backdrop 1 → 2`);系统 Win11 backdrop(2/3)**不透明**,透不出壁纸 → "看得见的整块玻璃"只能走 legacy accent 通道。最坏情况对比度已量化(45% 浓度下亮壁纸处约 2.1:1,70% 约 4.5:1),默认浓度待用户定。

### 编辑可靠性(用户拍板:必须有编辑,不能让人去开记事本)
- **修掉一个假承诺**:外部变更监听此前**从未生效**(前端两处路径比较写错:`getTab(S.cur)` 传对象、`S.cur === p` 比字符串);现在外部改盘会真自动重载,编辑中只提示、不动草稿。路径比较统一走 `normPath()`(反斜杠/大小写无关)。
- **不再静默丢内容**:新增关窗守卫(后端 `CloseRequested` 拦下并发 `close-requested` → 前端三选弹窗 → `allow_close` 放行);关标签 / 切库 / 从磁盘刷新前同样走三选(保存 / 不保存 / 取消),替代原来只有"放弃"的 `window.confirm`。
- **原子写**:同目录临时文件 → sync → rename;中途失败原文件不动,不留半截正文。
- **换行与 BOM 不再被改掉**:textarea 会把 CRLF 归一成 LF,保存时按原文件风格还原(实测 CRLF 保留)。
- **写前冲突检测**:后端记住"读出来时"的指纹,磁盘被外部改过则返回 `CONFLICT|<路径>`;前端弹「覆盖 / 取消」,**取消时磁盘不动、草稿不丢**。
- **Ctrl+S** 保存(此前根本没有保存快捷键);保存失败不再清脏标记、不退出编辑态。
- **扩展名口径统一**:树 / 打开 / 保存 / 写回 / 对话框 / 拖放共用一份清单(`md markdown mdx html htm`,外加显式打开 `.txt`),消除"树里有、点开报错"。
- 验证:CDP 端到端 21 项全过(CRLF 保留、原子写无残留、冲突覆盖与取消、watcher 真生效、关窗守卫拦住且先存后关、`.txt` 可开可存、Ctrl+S 真按键存盘)。

### 窗口:出生在副屏 + 几何改物理坐标
- **默认浓度 40%**(用户定调,比 pebrel 的 45% 再透一点;`weak/medium/strong = 20/40/70`)。
- **窗口 geometry v2**:`window.json` 改存**物理像素**,还原时按坐标找显示器 → 跨屏(225% 主屏 ↔ 200% 副屏)来回不再失真;老文件(v<2)仍按逻辑像素读,读完自动升级。
- **不再"先露面再搬家"**:窗口以 `visible:false` 创建,位置与玻璃都上好才 `show()` → 用户主屏**不会闪**。实测:`FIRST visible real window: 3880,40`(出生即在副屏)、`touchedPrimaryScreen=False`。
- **自动化专用开关** `TMMD_TEST_NOACTIVATE=1`:用 `SW_SHOWNOACTIVATE` 显示 + 打 `WS_EX_TOOLWINDOW`(不进任务栏、不抢前台),把测试实例与用户桌面彻底隔开。

### 编辑器(编辑第二批)
- **新建 / 另存为 / 重命名 / 删除**:新建可带子目录并直接进编辑;重命名/删除只对"库内文件"开放;删除走**系统回收站**(`SHFileOperationW` + `FOF_ALLOWUNDO`,先剥 `\\?\` 前缀),不做永久删。快捷键 `Ctrl+N` / `Ctrl+Shift+S` / `F2` / `Delete`,并进文件抽屉与树右键菜单。
- **Tab 缩进**:单点插两空格、跨行选区整块缩进、`Shift+Tab` 反缩进(此前按 Tab 会把焦点跳走)。
- **编辑态查找替换**:`Ctrl+H` 调出查找条(区分大小写、`n/m` 计数、替换当前 / 全部替换),每次改动进撤销栈。
- **撤销栈按标签隔离 + 上限 200**:切走再切回仍能撤销(此前是全局单例,切标签即全丢)。

### v1.8 运行验证(2026-10-25,全绿)

**跑道**:`e2e/r12d-full.mjs` **81/81** · `e2e/r12e-editor.mjs` **25/25** · `e2e/r12f-v18.mjs` **43/43**(新增) · `e2e/r12g-visual24.mjs` **24/24**(新增)。
隔离实例跑在副屏、不抢前台、不进任务栏;`TMMD_CONFIG_DIR` + `WEBVIEW2_USER_DATA_FOLDER` 双隔离,测试实例完全不碰用户真实配置与标签。

**运行验证抓到并修掉的 5 个真缺陷(全是静态检查漏掉的)**:

1. **保存/冲突路径 TypeError** —— i18n 批量的替换把 `String(trErr(e))` 写成 `StringtrErr(e)`,`writeTabContent` 的 catch 一执行就 `ReferenceError`;`printCurrent` 同款。
2. **i18n 调用被局部 `t` 遮蔽** —— `activateTabRaw(t, opts)` 的参数、`closeTab` 的局部都叫 `t`,`t('toast.x')` 变成"把 tab 对象当函数调"→ TypeError:**读文件失败提示**与**关脏标签冲突**两条路全崩。已改名 `tab`,并加源码级回归(r12f A4)。
3. **导出 HTML / PDF 恒失败** —— `getTab(S.cur)` 传的是对象 `{abs,raw}` 而非路径,恒 `undefined`,点导出永远"还没有打开任何文档";三处(`buildStandaloneHtml`/`exportCurrentHtml`/`exportCurrentPdf`)全修。
4. **PDF 直出找不到浏览器** —— 只查 ProgramFiles 三处固定路径,而本机没装 Edge/Chrome。已补注册表 `App Paths`(HKLM/HKCU)+ Brave/Vivaldi/Chromium + `TMMD_PDF_BROWSER` 显式指定,失败给可读提示(改用「打印 / 存 PDF」)。
5. **控制台闪窗** —— `reg` / `cmd /C start` / 更新器 `powershell` 都没加 `CREATE_NO_WINDOW`:GUI 进程起控制台子进程时 Windows 会新建**可见的**控制台窗口,闪在用户桌面上(用户抱怨"疯狂弹主屏幕"的一类真源)。5 处 spawn 统一走 `hidden_cmd()`。

**其它随验证落地的改动**:
- i18n 补**细节层**翻译(`ERR_TAIL_MAP`:Windows 中文系统消息「拒绝访问/找不到文件/被占用」+ PDF 浏览器相关几条),EN/JA 界面不再出现"英文前缀 + 中文后半句";删除 `err.tooBig`/`err.onlyExt` 的**重复键**(后者覆盖前者,新文案静默失效)。
- 代码块底板透明度加上下限 `max(90%, …)`(低浓度档此前只有 0.8,低于设计要求的 α≥0.9)。
- 新增全局 `:focus-visible` 焦点环(键盘 Tab 可辨;此前除三个输入框外没有任何焦点提示)。
- 圆角字面量归位到 4/6/8/12 四档(消除 3px/7px/10px 随手值)。
- 后端新增测试缝 `TMMD_CONFIG_DIR`;`tools/verify/` 新增 `probe.mjs`(一行读运行态)、启动器加 `WEBVIEW2_USER_DATA_FOLDER` 与 PID 落盘,`stopall.ps1` 改**身份定位**(不再按进程名杀,避免误杀用户自己那台)。
- 窗口几何实测:出生即在副屏 `rect=(3900,60) 2197x1456`、`touchedPrimaryScreen=False`、`WS_EX_TOOLWINDOW` 已打。
- 实测帧率:5000 行滚动 avg **6.9ms** / p95 **7.1ms**(块节点 10000);真 Win32 连续改尺寸 avg **6.9ms** / p95 **7.7ms**。
- **24 条视觉检查表逐条销项 24/24**(逐条判据见 `docs/2026-10-25-验证清单.md` §4)。

详细判据、复跑命令与踩过的 10 个坑:`docs/2026-10-25-验证清单.md`。
