## v1.8.7 · 2026-10-25(复核抓到的 5 处:帧率假绿 / 同极反噬 / 打印灰影 / 断言太松)

只读复核对 v1.8.6 的文字晕提了 5 条,全部落实:

1. **帧率核验一直是空转(既有假绿)**。`r12f` G 组与 `r12g` 第 13 条找的是 `.reader-scroll` —— 全仓没有这个类,
   于是回落到 `document.scrollingElement`(html);而 `html,body{height:100%}` + `body{overflow:hidden}` +
   `.layout{overflow:hidden}` 把视口锁死 ⇒ `scrollTop` **恒为 0**,60 帧全是空闲帧。也就是说"5000 行滚动 p95 7.1ms"
   从来没滚过那篇文档,文字晕的光栅成本从未被量到。修:换成真正的滚动容器 `#reader`,并加
   `G4 滚动真的发生了(scrollTop > 0)` / r12g 第 13 条同口径断言,防止再退化成空转。
2. **深色主题里"深字压亮底"被深晕反噬**:`mark.srh-hit.now`(橙底 + `#1d2021` 字,原本 6.5:1)与
   `.win-close:hover`(红底深字)被暗晕把紧邻底压暗 → 2.1:1 ✗。这两处改成**反相亮晕**。
3. **导出/打印会带灰影**:app.css 被原样内联进导出 HTML,而导出模板的 `@media print` 强制 `background:#fff;color:#111`
   —— 深色主题的黑晕落在白纸上,每个字一圈淡灰。修:打印块里把 `--text-halo / --title-halo` 置 `none`。
4. **断言只判"非 none"**:换成看不见的 `0 0 0 transparent` 也能全绿。升级为"**可用**":≥2 层、至少一层 α≥0.5、带几何。
5. **控件只抽第一个 / placeholder 是盲区**:改为全部 `button/input/select/textarea` + 全部 `::placeholder` 各扫一遍;
   并在 CSS 里显式写 `input::placeholder, textarea::placeholder { text-shadow: inherit }`(placeholder 在 UA shadow tree 里,
   TreeWalker 扫不到,不能靠"碰巧继承")。

回归:r12f 51→53 条(G4 + I4),合计 **183**(81+25+53+24)。

## v1.8.6 · 2026-10-25(玻璃模式下文字被亮壁纸洗没 → 全站文字晕)

用户实拍:侧栏在玻璃模式下"字完全消失"。量了那张图,不是错觉:

| 文字档 | 对背景 (122,126,120) 的对比 | 判据 |
|---|---|---|
| `--fg-faint`(#7c6f64)"目录/最近打开" | **1.18:1** | 正文要 ≥4.5:1 |
| `--fg-dim`(#a89984)目录项 | **1.49:1** | 同上 |
| `--fg`(#ebdbb2)正文 | 3.0:1 | 同上 |

而且**换色救不了**:那块背景亮度 L≈0.21,任何实心字色对它最多 ~3.0:1(连最亮的米白也刚好 3.0)。
所以按既定配方(skill `over-media-text-readability`)走**局部对比**:

- 全站文字加一层**主题自适应晕**:深色主题暗晕、浅色主题亮晕(`--text-halo` / `--title-halo`,标题一档更强);
  玻璃模式下"字心 vs 紧邻像素"从 **4.89 → 6.48:1**(紧三档,扫了 4 档强度选的:5.90 / **6.48** / 7.15)。
- 关键补丁:`button/input/select/textarea { text-shadow: inherit }` —— Chromium 的 UA 样式表会把这些控件的
  `text-shadow` 重置成 `none`,只写 `body{...}` 覆盖不到它们(按钮文字会继续被洗没)。
- 实色模式下这层晕几乎不可见(暗晕压暗底、亮晕压亮底),**观感不变**;`text-shadow` 烘进文字合成层,
  滚动只合成不重绘(帧率断言 G2/G3 盯着)。
- **不动你拍板的 40% 浓度**:远景对比只能靠压暗表面提高,那等于推翻 40%,不做;这里只把"字能不能认出"解决掉。
- 新增断言 `r12f` **I 组 3 条**:逐**非空白文本节点**审计 `text-shadow` 覆盖(深/浅两主题各扫一次,坏数必须为 0)、
  控件继承链已接回、浅色主题的晕确实是反相亮晕。

## v1.8.0 · 2026-10-25(已打 tag;发布资产随 1.8.1 上传)

### 整窗一整块玻璃(用户定调:对标 pebrel 的"一整块玻璃",不走规范式分层)
- **单一浓度**:四路 `--glass-base/chrome/reader/pop` 收成 `--glass`;氛围档 weak/medium/strong = 20/**40**/70(**默认 40** 为用户定调,见 v1.8.1;pebrel 配置里的原值是 `opacity=0.45`)。老存档按 `1-(1-base)(1-reader)` 折算成单一浓度,视觉不跳。
- **只画一层**:`html` / `.layout` / 铬层 / 正文区不再各自叠浓度(旧模型 base 被叠 2–3 次,总浓度不受控);`body` 成为唯一浓度层。
- **DWM 只做模糊**(与 pebrel 实测配方对齐):`glassSplit(conc)` 现在返回 `{ dwm: 1, css: conc }` —— 浓度全由页面层画,DWM 只保住 accent 通道(alpha 不能取 0,否则部分 DWM 版本会跳过,玻璃整块消失;pebrel 同样写 `0x01000000`)。依据其源码:`blur=acrylic` 首选 WinAppSDK `DesktopAcrylicController`(`tint=0`、`luminosity=0`),回落 `WCA accent state 4`;它的 `opacity=0.45` **只乘自己画的背景色**(壳色/标题栏/侧栏/卡底),文字与图标始终不透明 —— 与我们"单一浓度 + 文字 alpha 独立"的模型一致,滑条也因此诚实(写多少就得到多少)。
- **实测(副屏真实合成像素,同一张壁纸)**:跨表面边界同高度取样(顶栏→正文、侧栏→正文、侧栏底→正文、设置页导航→主体)Δ = 0.0–1.4 luma → **"一整块"成立**;正文留白沿壁纸连续变化(135→133→108→96→103→131→127),无分块跳变。最坏情况对比度(`--fg` 压在窗内最亮壁纸带):conc 45 → 中位 3.71:1 / 最坏 2.15:1;conc 70 → 6.35:1 / 3.21:1(纯白壁纸模型对应 2.17:1 / 4.55:1)。**默认取 40%**(实测见 v1.8.1)。
- 另注:只设 `DWMWA_USE_HOSTBACKDROPBRUSH=1` 而不接 WinAppSDK 的 composition target **无任何视觉变化**(实测前后像素完全一致);pebrel 那条现代路线需要 ~200 行 COM 互操作(WinAppSDK 1.8 + `DesktopWindowTarget`),而我们的 WCA 回落路径与它的回落路径同级。
- **内容板不再是补丁**:31 处 `background: var(--bg2|--bg3|--code-bg|--bg)` 换成 `--surface-plate`(浓度 +22)/`--surface-plate-strong`(+40);代码块不再强制不透明。
- 修:`applyAtmos` 还在往存档写已废的 `base/chrome/reader/pop`(全是 `undefined`)→ 氛围档按钮失效;`.setpage-search` 在设置页里又垫了一层窗口级浓度。
- 实测(副屏抓真实合成像素):Mica 确认真机生效(`backdrop 1 → 2`);系统 Win11 backdrop(2/3)**不透明**,透不出壁纸 → "看得见的整块玻璃"只能走 legacy accent 通道。最坏情况对比度已量化(45% 浓度下亮壁纸处约 2.1:1,70% 约 4.5:1);**默认取 40%**(用户 2026-10-25 定调,实测值见 v1.8.1)。

### 编辑可靠性(用户拍板:必须有编辑,不能让人去开记事本)
- **修掉一个假承诺**:外部变更监听此前**从未生效**(前端两处路径比较写错:`getTab(S.cur)` 传对象、`S.cur === p` 比字符串);现在外部改盘会真自动重载,编辑中只提示、不动草稿。路径比较统一走 `normPath()`(反斜杠/大小写无关)。
- **不再静默丢内容**:新增关窗守卫(后端 `CloseRequested` 拦下并发 `close-requested` → 前端三选弹窗 → `allow_close` 放行);关标签 / 切库 / 从磁盘刷新前同样走三选(保存 / 不保存 / 取消),替代原来只有"放弃"的 `window.confirm`。
- **原子写**:同目录临时文件 → sync → rename;中途失败原文件不动,不留半截正文。
- **换行与 BOM 不再被改掉**:textarea 会把 CRLF 归一成 LF,保存时按原文件风格还原(实测 CRLF 保留)。
- **写前冲突检测**:后端记住"读出来时"的指纹,磁盘被外部改过则返回 `CONFLICT|<路径>`;前端弹「覆盖 / 取消」,**取消时磁盘不动、草稿不丢**。

**运行验证抓到并修掉的 5 个真缺陷(全是静态检查漏掉的)**:

1. **保存/冲突路径 TypeError** —— i18n 批量的替换把 `String(trErr(e))` 写成 `StringtrErr(e)`,`writeTabContent` 的 catch 一执行就 `ReferenceError`;`printCurrent` 同款。
2. **i18n 调用被局部 `t` 遮蔽** —— `activateTabRaw(t, opts)` 的参数、`closeTab` 的局部都叫 `t`,`t('toast.x')` 变成"把 tab 对象当函数调"→ TypeError:**读文件失败提示**与**关脏标签冲突**两条路全崩。已改名 `tab`,并加源码级回归(r12f A4)。
3. **导出 HTML / PDF 恒失败** —— `getTab(S.cur)` 传的是对象 `{abs,raw}` 而非路径,恒 `undefined`,点导出永远"还没有打开任何文档";三处(`buildStandaloneHtml`/`exportCurrentHtml`/`exportCurrentPdf`)全修。
4. **PDF 直出找不到浏览器** —— 只查 ProgramFiles 三处固定路径,而本机没装 Edge/Chrome。已补注册表 `App Paths`(HKLM/HKCU)+ Brave/Vivaldi/Chromium + `TMMD_PDF_BROWSER` 显式指定,失败给可读提示(改用「打印 / 存 PDF」)。
5. **控制台闪窗** —— `reg` / `cmd /C start` / 更新器 `powershell` 都没加 `CREATE_NO_WINDOW`:GUI 进程起控制台子进程时 Windows 会新建**可见的**控制台窗口,闪在用户桌面上(用户抱怨"疯狂弹主屏幕"的一类真源)。5 处 spawn 统一走 `hidden_cmd()`。
